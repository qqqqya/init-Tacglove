# 07 SK6805的GPIO+DWT与PWM+DMA方案对比

## 1. 结论

当前工程应继续保留已经验证稳定的 `TIM3_CH3 PWM + DMA` 方案，不再退回 `GPIO + DWT` 软件时序方案。

GPIO+DWT适合灯数少、无RTOS或早期快速点灯；PWM+DMA更适合本工程后续同时运行FreeRTOS、USART2 DMA和micro-ROS。现在颜色错乱、偶发白光的问题已经消失，说明此前主要矛盾确实是软件时序容易被执行路径和中断扰动，而不是亮度值本身。

## 2. 两种方案如何产生波形

### 2.1 GPIO+DWT

CPU先拉高PB0，再读取DWT周期计数器等待指定周期，随后拉低并再次等待。每一个0/1 bit都由CPU顺序执行GPIO写入和延时。

```text
CPU：写高 -> DWT等待T0H/T1H -> 写低 -> DWT等待 -> 下一个bit
PB0：由CPU每bit直接翻转
```

DWT比纯NOP可靠，因为它以硬件周期计数器判断经过时间；但整个波形仍由软件指令串行拼接，GPIO写入开销、中断插入和主频配置都会进入实际时序。

### 2.2 PWM+DMA

CPU先把六颗灯的GRB数据编码成CCR比较值数组。TIM3固定产生1.2 us周期，DMA在每个码元更新CCR3，硬件决定本码元是0.3 us高电平还是0.9 us高电平。

```text
CPU：构建比较值数组 -> 启动一次DMA -> 等待完成
DMA：逐项写TIM3_CCR3
TIM3：连续输出固定周期PWM
PB0：由TIM3_CH3硬件输出
```

## 3. 关键差异

| 对比项 | GPIO+DWT | TIM3 PWM+DMA |
|---|---|---|
| 码元周期来源 | CPU指令与DWT等待共同形成 | TIM3硬件计数器形成 |
| 高电平宽度 | CPU拉高、延时、拉低 | CCR3比较值决定 |
| 编译优化影响 | DWT计数本身稳定，但GPIO访问和循环开销仍可能变化 | 数据发送阶段基本不受O0/O2影响 |
| 中断影响 | 中断插入会拉长某一高/低电平；若全程关中断则影响RTOS | 中断不会改变TIM3输出时序 |
| 主频变化 | 必须保证SystemCoreClock和DWT换算正确，并重新核对GPIO指令开销 | 必须按新的TIM3输入时钟重算PSC、ARR和CCR |
| CPU占用 | 发送期间CPU逐bit忙等 | CPU只编码和启动DMA；当前 `commit()` 仍等待完成，但不参与逐bit翻转 |
| RTOS兼容性 | 容易因任务/中断扰动，或为了保时序而形成长临界区 | 更适合FreeRTOS与micro-ROS并行运行 |
| RAM占用 | 很小，只需颜色缓存 | 较大，需要完整DMA比较值帧 |
| 外设占用 | 一个普通GPIO和DWT | TIM3_CH3与一个DMA通道 |
| 扩展灯数 | 灯越多，CPU忙等越久 | 灯越多主要增加DMA缓冲和传输时间 |
| 故障定位 | 需结合编译版本和中断场景复现 | ARR/CCR、DMA长度和物理信号边界更明确 |
| 当前上板结果 | 出现过颜色错、白光和亮度异常 | 已稳定运行，颜色和亮度正常 |

## 4. 当前PWM+DMA参数

当前工程参数来自 `glove_UMI_APP.ioc` 和LED Driver：

| 参数 | 当前值 | 计算结果 |
|---|---:|---:|
| TIM3输入时钟 | 170 MHz | 单计数约5.882 ns |
| PSC | 0 | 计数频率170 MHz |
| ARR | 203 | 204计数，即1.2 us/码元 |
| 逻辑0 CCR | 51 | 高电平约0.3 us |
| 逻辑1 CCR | 153 | 高电平约0.9 us |
| 数据码元 | 6 × 24 = 144 | 数据段172.8 us |
| 前置低电平码元 | 256 | 307.2 us |
| 后置低电平码元 | 256 | 307.2 us |
| DMA总项数 | 656 | 完整帧约787.2 us |
| DMA缓存 | `uint32_t[656]` | 2624 bytes |

前后都放低电平的目的，是保证上一次发送、DMA启动边界和本次锁存之间都有足够裕量。它牺牲了约0.6 ms传输时间和2.6 KB RAM，换来清晰稳定的帧边界，对当前六灯低刷新率场景是合理取舍。

## 5. 对编译优化与主频的回答

- GPIO+DWT不是“改O2就一定失效”，但优化等级会改变软件路径开销，任何依赖GPIO写操作附近指令耗时的实现都应该重新测量；中断仍是更大的不确定因素。
- PWM+DMA在O0和O2下不需要重新标定NOP，因为已经没有NOP码元时序；只要TIM3输入时钟、PSC、ARR和CCR不变，硬件输出时序就不变。
- 如果修改系统时钟，PWM+DMA仍必须重新计算参数并用逻辑分析仪确认。降低主频并不能解决3.3 V直驱5 V灯珠的电平裕量，也没有必要为了灯带单独降低整机频率。
- 当前Driver在初始化时检查 `PSC=0`、`ARR=203` 和DMA资源，可防止CubeMX参数被改动后静默输出错误波形。

## 6. 当前实现仍需知道的边界

1. `bsp_led_driver_commit()` 会等待本帧DMA完成，约0.79 ms内不主动让出当前任务，但中断保持开启，PWM波形也完全由硬件产生。当前灯效刷新频率很低，这个占用可接受；后续如果刷新频率明显提高，再考虑非阻塞提交或用同步对象等待DMA完成。
2. TIM3 DMA1_Channel1、USART2 RX DMA1_Channel2、USART2 TX DMA1_Channel3通道独立。LED DMA优先级Very High，USART2 DMA优先级High，当前不存在通道冲突。
3. DMA稳定只解决数字时序问题，不能提高PB0高电平电压。3.3 V直接驱动5 V SK6805当前实测可用，但量产硬件仍应评估74AHCT等电平转换、线长、地弹、温度和批次差异。
4. 后续任何TIM3时钟、PSC、ARR、CCR、DMA数据宽度、复位码元数或PB0复用变化，都必须同步修改 `.ioc`、Driver注释和波形验证记录。

## 7. 最终选择

阶段3继续使用当前PWM+DMA实现。micro-ROS接入后，即使USART2 DMA中断、FreeRTOS调度和Agent通信同时发生，SK6805码元仍由TIM3输出，不会因为通信负载产生白光或错色。这正是本项目从GPIO+DWT切换到PWM+DMA的核心收益。
