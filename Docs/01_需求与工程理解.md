# 01 需求与工程理解

## 1. 当前项目定位

当前工程 `Tacapp_init` 是五指数采 UMI 板的开发阶段单体固件，不包含 Bootloader、APP1/APP2 分区、IAP、YMODEM 和固件加密。固件从 `0x08000000` 启动并使用完整 512 KB Flash。

后续所有代码、配置和文档修改均在 `Tacapp_init` 中进行。`Tacglove` 只作为最终工程架构、FreeRTOS 和 micro-ROS 移植参考，`qyan_Tacglove` 只作为 BSP、按键消抖和采集状态机参考。

## 2. 已确认硬件

- MCU：STM32G474RET6，系统时钟 170 MHz。
- SK6805：共 6 颗，数据从 PB0 发出，串联方向为 LED7、LED6、LED5、LED4、LED3、LED2。
- PB0：3.3 V GPIO 直接驱动 SK6805 DIN，当前不增加电平转换，GPIO 速度为 Very High。
- PA11：数采按键，内部上拉，按下接地，低电平有效。
- PB9：有源蜂鸣器驱动，低电平有效，高电平关闭。
- USART2：PA2/PA3，经 CH340 连接 PC，是正式 MCU-PC 通道。
- USART1：当前禁用。
- 相机：通过 USB Hub 直接连接 PC，第一阶段不做相机联动。

## 3. 灯珠业务映射

| 业务对象 | 原理图灯号 | SK6805发送序号 |
|---|---:|---:|
| 采集指示灯 | LED7 | 0 |
| 相机5 | LED6 | 1 |
| 相机4 | LED5 | 2 |
| 相机3 | LED4 | 3 |
| 相机2 | LED3 | 4 |
| 相机1 | LED2 | 5 |

鱼眼相机当前不设置指示灯，LED7作为系统状态指示灯。

## 4. 第一阶段目标行为

上电后先执行一次板级 RGB 通道验证：6颗灯全红、全绿、全蓝，然后熄灭。随后进入产品状态显示：

| 颜色 | 状态 | 含义 |
|---|---|---|
| LED2-LED6绿色 | 闪烁 | 上电自检中 |
| LED2-LED6绿色 | 常亮 | 自检通过，待机，录制关闭 |
| LED7蓝色 | 闪烁 | 进入数采准备状态 |
| 蜂鸣器 | 短鸣 | 准备结束，可以开始数采 |
| LED7蓝色 | 常亮 | 数据采集进行中 |
| 6颗灯红色 | 常亮 | 硬件、通信或数据故障 |

当前按键可以区分单击、双击和长按。单击从待机进入“LED7蓝色闪烁、蜂鸣器短鸣、LED7蓝色常亮”；采集中再次单击则短鸣并返回待机。双击和长按当前只提供可辨认的板级测试反馈，不改变主状态。

## 5. 软件分层

```text
Core
  CubeMX生成的时钟、GPIO、DMA、USART2、RTC和启动代码

BSP Driver
  只处理GPIO、电平有效性、SK6805 GRB编码和单线时序

BSP Handler
  只处理LED2-LED7业务映射和按键读取

Tasks
  当前只有led_task和key_task；key_task直接调用led_task对外动作接口

Middleware
  FreeRTOS；后续加入micro-ROS
```

## 6. Service 与 Tasks 的区别

`Service` 不等同于 `Tasks`。

- `Tasks` 表示具有独立 FreeRTOS 执行上下文的循环入口，负责等待、周期和调度。
- `Service` 表示可被任务调用的业务能力，例如状态管理、版本信息、时间同步和数据封装，本身不一定创建任务。

参考 `Tacglove` 把部分任务入口放在了 `Service` 目录中，功能上可以运行，但职责有混合。当前开发阶段只保留 `BSP/Tasks`；等micro-ROS和业务状态真正需要时，再增加 `Application` 或 `Service`。

## 7. MCU-PC通信方向

最终采用 MCU 直接运行 micro-ROS Client 的方案：USART2 DMA custom transport 连接 PC 端 micro-ROS Agent。自定义 UART 二进制协议加 rclpy 桥接的方案不作为当前主线。
